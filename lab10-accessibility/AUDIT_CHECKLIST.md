# Контрольный лист аудита доступности

## Что проверить вручную
- Tab / Shift+Tab: логичный порядок фокуса и видимый контур.
- Enter: переход по ссылкам; Enter/Space: отправка кнопки.
- У каждого поля есть видимый `<label>`.
- Есть ссылка пропуска навигации, `header`, `nav`, `main`, `footer`, заголовки по иерархии.
- Сообщения поиска/формы объявляются через `role="status"` и `aria-live`.
- Проверить контраст в DevTools: обычный текст 4.5:1, крупный текст 3:1.

## Таблица исправлений (подтвердить собственным аудитом)
| Проблема, которую нужно проверить | Исправление в проекте |
|---|---|
| Нет способа пропустить повторяющуюся навигацию | Ссылка «Перейти к содержимому» |
| Поля формы/поиска без программной подписи | Связанные label + id |
| Фокус клавиатуры не виден | `:focus-visible` |
| Динамический результат не объявляется вспомогательным технологиям | `role=status`, `aria-live` |
| Нечёткая структура страницы | Семантические header/nav/main/footer и заголовки |

**Важно:** строки таблицы — чек-лист типовых рисков, а не выдуманный отчёт Axe. Снимки «до» делай на исходной версии/отдельной копии, снимки «после» — на этом проекте.
